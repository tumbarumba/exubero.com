Items at the top of the backlog:

- clear value and acceptance criteria
- clear size
- in focus, not much uncertainty

Items further down:

- value well understood
- size not clearly understood (does it need splitting?)
- acceptance criteria and exact tasks not so much

Items further down still:

- rough idea of value
- not clear how big it is
- no idea how to accept

The fuzzy backlog is good. Too much focus implies waste, as analysis work was done on a backlog item that may never be implemented, or the analysis gets out of date
